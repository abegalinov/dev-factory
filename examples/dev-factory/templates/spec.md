# Spec: <title> (issue #<n>)

## 1. Summary
What changes for whom, in two or three sentences.

## 2. Scope
In scope / out of scope, as bullet lists.

## 3. Behavior
One subsection per screen, endpoint or flow. Describe states (loading, empty, error),
permissions (guest vs signed-in) and edge cases.

## 4. Acceptance criteria
Numbered, each one testable by a single test.

## 5. Test scenarios
Which tests prove the criteria (unit, widget, e2e, integration), with the file each
belongs in.

## 6. Technical notes
Data model or API changes, migrations, affected components.

## 7. Assumptions (reviewer: reject any that are wrong)
Everything decided without an explicit answer from a maintainer.
